# Deployment Guide

Architecture: **frontend on Vercel, API + Postgres + Redis on Render.**

```
Browser ──> Vercel (Next.js frontend)
                │  NEXT_PUBLIC_API_URL
                ▼
        Render web service (Fastify API, routes under /api)
                │                │
        Render Postgres    Render Key Value (Redis)
```

Because the API runs as a long-running process on Render, the outbox worker and
expiry sweeper start in-process automatically — no cron setup needed.
(The `/api/internal/tick` endpoint still exists and is handy for manual kicks,
guarded by `CRON_SECRET`.)

---

## 1. Backend on Render (one click via Blueprint)

1. Push this branch to GitHub (already done: `origin/staging`).
2. Render Dashboard → **New → Blueprint** → select the `dcablorh/cheque` repo and the `staging` branch.
3. Render reads `render.yaml` and provisions:
   - `cheque-api` — Node web service (build: pnpm install + build API and its workspace packages; start: `node api/dist/server.js`; health check: `/api/health`)
   - `cheque-db` — free Postgres (`DATABASE_URL` is wired automatically)
   - `cheque-redis` — free Key Value / Redis, internal-only (`REDIS_URL` wired automatically)
   - `JWT_SECRET`, `OTP_SALT`, `CRON_SECRET` — generated once and kept stable
4. At sync time Render prompts for every `sync: false` variable — paste:
   - `EMAIL_API_KEY` (Resend — required in production)
   - `NEXT_PUBLIC_APP_URL` — your **Vercel frontend URL** (e.g. `https://cheque.vercel.app`); this drives CORS
   - The Stellar account secrets from `.env.local`: `CONTRACT_ADMIN_SECRET`, `CLAIM_AUTHORITY_PUBLIC`/`SECRET`, `GUARDIAN_SECRET`, `FUNDING_ACCOUNT_SECRET`, `SETTLEMENT_ACCOUNT_PUBLIC`/`SECRET`, `FEE_SOURCE_PUBLIC`/`SECRET`, `CHANNEL_ACCOUNT_SECRETS`
   - Optionally `FX_GHS_PER_USDC`, `ENABLED_CORRIDORS` (defaults apply otherwise)
5. Deploy, then verify: open `https://cheque-api-xxxx.onrender.com/api/health` → expect `"status":"ok"` and `"database":"connected"`. Check the logs for `Database migrations verified and up-to-date.` — migrations run automatically on boot.

### Free-plan caveats
- Free web services **spin down after ~15 min idle** → first request has a ~30s cold start. Use the **starter** plan for launch.
- Free Postgres **expires after 30 days** — upgrade before then or the data is gone.

---

## 2. Frontend on Vercel

1. Vercel → **Add New → Project** → import `dcablorh/cheque`.
2. Vercel reads `vercel.json`: a single `frontend` service (Next.js, root `frontend/`).
3. Set the project env var:

   | Variable | Value |
   |---|---|
   | `NEXT_PUBLIC_APP_URL` | `https://<your-vercel-domain>` |
   | `NEXT_PUBLIC_API_URL` | `https://cheque-api-xxxx.onrender.com/api` ← **your Render API URL + `/api`** |

   The `/api` suffix matters: all API routes live under that prefix.
4. Deploy.

> Alternative (no CORS at all): keep `NEXT_PUBLIC_API_URL=/api` on the frontend and add a rewrite in `vercel.json`:
> `{ "source": "/api/(.*)", "destination": "https://cheque-api-xxxx.onrender.com/api/$1" }`.
> The browser then talks only to the Vercel domain and Vercel proxies to Render.

## 3. Environment variable reference

Every variable the API reads (from `packages/shared/src/env.ts`). Defaults exist for
almost everything, so only the **Required in production** rows must be set by hand.

### 3.1 Auto-wired by the Render blueprint (you never touch these)

| Variable | What it does |
|---|---|
| `DATABASE_URL` | Postgres connection string — the app's only datastore (cheques, users, ledger, outbox). Wired from the `cheque-db` Render database. |
| `REDIS_URL` | Redis (Valkey) connection string — rate limiting, OTP session store, BullMQ outbox queue, submission idempotency. Wired from `cheque-redis`. Internal `redis://` URL, no TLS needed inside Render's network. Falls back to in-memory if unset (not recommended in prod). |
| `PORT` / `HOST` | HTTP port/bind address. Render injects `PORT`; `HOST` defaults to `0.0.0.0`. |
| `JWT_SECRET` | Signs sender auth JWTs (access + refresh tokens). Auto-generated (≥32 chars) by the blueprint. |
| `OTP_SALT` | Pepper used when hashing OTPs before storage. Auto-generated by the blueprint. |
| `CRON_SECRET` | Bearer secret for `POST /api/internal/tick` (manual outbox/sweep kicks). Auto-generated. |

### 3.2 You paste at Render blueprint sync time (or Dashboard → cheque-api → Environment)

| Variable | Required in prod? | What it does | Where to get it |
|---|---|---|---|
| `EMAIL_API_KEY` | **YES** | Resend API key — sends sender-login OTPs, payee claim OTPs and cheque alert emails. Without it the API refuses to boot in production. | [resend.com](https://resend.com) → API Keys → Create. Verify your sending domain so mail comes from your domain, not the shared test sender. |
| `NEXT_PUBLIC_APP_URL` | **YES** | The public frontend URL. Used for CORS (the API only accepts browser calls from this origin) and for building claim links inside emails. | Your Vercel domain, e.g. `https://cheque.vercel.app` (deploy frontend first, or edit later). |
| `CONTRACT_ADMIN_SECRET` | recommended | Secret key of the Soroban contract **admin** — the account that can change contract params (min/max amount, lock time, pause). | Generated by `pnpm bootstrap:testnet` → copy from root `.env.local`. |
| `CLAIM_AUTHORITY_PUBLIC` | **YES** | Public key of the **claim authority** — the signer that authorizes cheque redemption on-chain. Shown to users / embedded in cheques. | `pnpm bootstrap:testnet` → `.env.local`. |
| `CLAIM_AUTHORITY_SECRET` | **YES** | Secret of the same account. Chain operations are **DISABLED** without it (API logs a warning and cheques can't be funded/redeemed on-chain). | `pnpm bootstrap:testnet` → `.env.local`. |
| `SETTLEMENT_ACCOUNT_PUBLIC` | **YES** | Public key of the **settlement account** — the USDC escrow float that pays out redeemed cheques (and receives CCTP transfers for cross-chain payouts). | `pnpm bootstrap:testnet` → `.env.local`. |
| `SETTLEMENT_ACCOUNT_SECRET` | **YES** | Secret of the settlement account. Required in production. | `pnpm bootstrap:testnet` → `.env.local`. |
| `FEE_SOURCE_PUBLIC` | **YES** | Public key of the **fee source** — pays the platform's share of Stellar transaction fees so user flows never depend on user account balances. | `pnpm bootstrap:testnet` → `.env.local`. |
| `FEE_SOURCE_SECRET` | **YES** | Secret of the fee source account. Required in production. | `pnpm bootstrap:testnet` → `.env.local`. |
| `GUARDIAN_SECRET` | no (reserved) | Secret key of the **guardian** account — designed for recovery/refund intervention on stuck cheques. Not yet wired into handlers; safe to set now. | `pnpm bootstrap:testnet` → `.env.local`. |
| `FUNDING_ACCOUNT_SECRET` | **YES** (feature-critical) | Secret of the **funder** — signs every on-chain operation the API submits (lock, redeem, refund) and is the fee-payer for Soroban txs. Missing → chain operations disabled. | `pnpm bootstrap:testnet` → `.env.local`. |
| `CHANNEL_ACCOUNT_SECRETS` | no | Comma-separated list of Stellar channel account secrets for transaction sequencing/parallelism. **Currently unused** — the channel pool is disabled in code (`chain-runtime.ts`) because leased signers caused `tx_bad_auth_extra`. Leave unset. | — |
| `FX_GHS_PER_USDC` | no | Cedi-per-USDC rate used to display GHS amounts (e.g. `15.500000`). Placeholder until a live quote service (SEP-38) feeds rates. | Set to your current rate; default `15.500000`. |
| `FX_NGN_PER_USDC` | no | Naira-per-USDC rate (default `1550.000000`). | Same. |
| `ENABLED_CORRIDORS` | no | Comma-separated corridor codes that accept new cheques: `GH,NG,US` (default all three). | Set to `GH` to launch Ghana-only. |

### 3.4 Optional — cross-chain (CCTP) payouts to Solana

Leave all unset to run Stellar-only. Setting them enables the CCTP redeem flow (`pnpm e2e:cctp`).

| Variable | What it does | Where to get it |
|---|---|---|
| `CCTP_TOKEN_MESSENGER_MINTER` | Contract ID of Circle's TokenMessengerMinter on Stellar — burns USDC for cross-chain transfer. | [Circle CCTP contract addresses](https://developers.circle.com/stablecoins/contract-addresses) (testnet + mainnet listed). |
| `SOLANA_RPC_URL` | Solana RPC endpoint used to deliver minted USDC on the destination chain. | `https://api.devnet.solana.com` (test), a paid RPC (Helius/QuickNode) for prod. |
| `SOLANA_USDC_MINT` | Solana USDC mint address — destination token account derivation. | Circle docs / Solana explorer (`4zMM9...` devnet, `EPjFW...` mainnet). |
| `IRIS_API_URL` | Iris API base URL (cross-chain messaging indexer). | Circle docs. |

### 3.5 Frontend (Vercel project → Settings → Environment Variables)

| Variable | What it does | Where to get it |
|---|---|---|
| `NEXT_PUBLIC_APP_URL` | The frontend's own public URL — used for canonical links/OG tags. | Your Vercel domain. |
| `NEXT_PUBLIC_API_URL` | Base URL the browser uses for API calls. **Must end in `/api`** because all API routes live under that prefix, e.g. `https://cheque-api-xxxx.onrender.com/api`. | Your Render web service URL. For local dev, create `frontend/.env.local` with `NEXT_PUBLIC_API_URL=http://localhost:3001/api`. |

### 3.6 Local development

Nothing to deploy: copy `.env.example` → `.env.local`, run `pnpm bootstrap:testnet` to generate
and fund all Stellar accounts (it writes the keys into `.env.local`), and run
Postgres + Redis via `docker-compose up -d` or `scripts/setup-db.sh`. See `docs/SETUP.md`.

> Production validation: with `NODE_ENV=production` the API **refuses to start** unless
> `CLAIM_AUTHORITY_SECRET`, `SETTLEMENT_ACCOUNT_SECRET`, `FEE_SOURCE_SECRET`,
> `EMAIL_API_KEY` are set and `JWT_SECRET` / `OTP_SALT` are non-default and ≥32 chars.

---

## 4. Post-deploy checklist

- [ ] `GET /api/health` returns `ok` / `database: connected`
- [ ] Sender email login works from the Vercel frontend (Resend OTP arrives)
- [ ] Send a test cheque on testnet; confirm funding + claim emails arrive
- [ ] Let a test cheque expire → sweeper queues the refund (check logs for `[sweeper]`)
- [ ] CCTP cross-chain quote works if `SOLANA_*` / CCTP vars are set
